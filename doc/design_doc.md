# Instagram CRM (MVP) 仕様書

## 概要

Instagramのリールへ投稿されたコメントに対し、自動で定型文を返信するローカルデスクトップアプリを開発する。

本プロジェクトは **MVP（Minimum Viable Product）** とし、最低限動作することを最優先とする。

AI機能は実装しない。

---

# 開発方針

- Rustをメイン言語とする
- Tauri 2を利用する
- サーバーは使用しない
- Webhookは利用しない
- Pull（ポーリング）方式を採用する
- GitHub Releasesで配布することを前提とする
- Windows・macOSに対応する
- 将来的な拡張を考慮した構成にする

---

# 技術スタック

- Rust
- Tauri 2
- tokio

# MVP機能

## 1. OAuthログイン

初回起動時のみInstagramアカウントを連携する。

### 要件

- 「Instagramと連携」ボタンを表示
- ブラウザでOAuth認証
- アクセストークン取得
- Keychain（macOS）/ Credential Manager（Windows）へ保存
- 次回以降は自動利用

---

## 2. バックグラウンド常駐

起動後はバックグラウンドで動作する。

### 要件

- Windows
  - タスクトレイ
- macOS
  - メニューバー

ウィンドウを閉じても終了しない。

終了は

```
Quit
```

のみ。

---

## 3. ポーリング

Webhookは利用しない。

一定間隔でInstagram Graph APIへ問い合わせる。

### デフォルト

```
30秒
```

設定ファイルから変更可能にする。

---

## 4. コメント取得

一定期間以内のコメントを取得する。

取得対象

- 自分のリール

---

## 5. 新規コメント判定

SQLiteへ返信済みコメントを保存する。

保存されていないコメントのみ返信する。

---

## 6. 自動返信

返信文は固定。

例

```
コメントありがとうございます！
```

設定画面から変更可能。

---

## 7. ログ

最低限以下を出力する。

- 起動
- OAuth成功
- コメント取得
- コメント返信成功
- コメント返信失敗
- APIエラー
- OAuth期限切れ

# エラー処理

## OAuth期限切れ

再ログイン画面を表示する。

---

## APIエラー

ログ出力のみ。

次回ポーリングで再試行。

---

## Rate Limit

HTTP 429を受けた場合は指数バックオフを行う。

例

- 30秒
- 60秒
- 120秒
- 240秒

成功したら30秒へ戻す。

---

# 非機能要件

- Rustらしい実装を行う
- async/awaitを利用する
- `unwrap()`は禁止（テストコード除く）
- 適切なエラーハンドリングを行う
- 責務を分離する
- 将来的な機能追加が容易な構成にする
- ログを十分に出力する
- メモリ使用量は100MB以下を目標とする

# Claude Codeへの実装方針

- Instagram Graph APIの最新仕様を公式ドキュメントで確認してから実装すること。
- OAuth認証は公式フローに従うこと。
- コメント取得・返信ともに公式APIのみを使用すること。
- 利用規約に反するスクレイピングや非公式APIは使用しないこと。
- アーキテクチャはレイヤー分離を意識し、API・認証・DB・サービス・UIを独立させること。
- 将来のエンハンスでリール単位の設定やAI返信を追加しやすい設計にすること。
- UIはシンプルで十分だが、利用者が設定変更や接続状態を確認できるようにすること。
